# application.yml 配置说明

本文档对应 `src/main/resources/application.yml`，说明各配置项含义、默认值与常见改法。

---

## 1. 基础运行环境

### spring.datasource（MySQL）

| 配置项 | 说明 |
|--------|------|
| `url` | JDBC 连接串，库名、时区、批量写入等参数 |
| `username` / `password` | 数据库账号 |
| `type` | 连接池类型，当前为 Druid |

商品记录、搜索条件等业务数据均存于此库。

### spring.redis

| 配置项 | 说明 |
|--------|------|
| `host` | Redis 地址，用于爬虫任务队列等 |
| `database` | Redis 库编号（0–15） |

### server.port

HTTP 服务端口，默认 `8111`。Web 管理页、邮件内「添加关注」等链接依赖此端口或反向代理域名。

### mybatis

| 配置项 | 说明 |
|--------|------|
| `mapper-locations` | XML 映射文件路径 |
| `map-underscore-to-camel-case` | 下划线列名转驼峰字段 |

## 2. 爬虫平台总开关

控制是否启动对应平台的定时抓取任务（与数据库里单条搜索条件的 `enable` 不同，这是全局开关）。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `mercari.enable` | `true` | 煤炉（Mercari）爬虫与通知 |
| `yahoo.enable` | `false` | 雅虎拍卖 / PayPay 跳蚤市场 |
| `rakuten.enable` | `false` | 乐天 |

示例：只用煤炉时：

```yaml
mercari:
  enable: true
yahoo:
  enable: false
rakuten:
  enable: false
```

---

## 3. 网络代理 network.proxy

访问日本站点（煤炉 API、商品图等）时若需代理，在此配置。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enabled` | `false` | 是否走 HTTP 代理 |
| `host` | `127.0.0.1` | 代理地址 |
| `port` | `7897` | 代理端口 |

注意：

- 访问 **企业微信** `qyapi.weixin.qq.com`、**QQ IMAP** 等国内服务时，建议代理关闭或确保不走代理，否则可能超时。
- 测试类 `WeChatNotifierTest` 中会强制 `network.proxy.enabled=false`。

---

## 4. 通知公共配置 notification

| 配置项 | 说明 |
|--------|------|
| `notification.host` | 对外可访问的**完整根 URL**（须含 `http://` 或 `https://`），用于邮件/微信里「添加关注」「不再关注」等链接，例如 `https://3yd4544930.zicp.fun` 或 `http://192.168.1.100:8111` |

须与你在路由器/内网穿透上暴露的地址一致，否则手机点邮件链接无法打开。

邮件/微信通知底部提供 **「不再关注该关键字」** 链接，点击后会：

1. 将对应搜索条件的 `enable` 设为 `0`
2. 取消该关键字的定时抓取任务

| 平台 | 链接路径 |
|------|----------|
| 煤炉 | `GET /mercari/disableSearchCondition?conditionId={id}` |
| 雅虎 | `GET /yahoo/disableSearchCondition?conditionId={id}` |
| 乐天 | `GET /rakuten/disableSearchCondition?conditionId={id}` |

## 5. 微信通知 wechat

与邮件**并行**发送；微信发送失败**不会**影响商品是否写入数据库（仍以邮件发送结果为准）。

### 5.1 总开关

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `wechat.enabled` | `false` | 是否启用微信推送 |

### 5.2 推送方式 type

| 值 | 说明 |
|----|------|
| `wework` | **企业微信群机器人**（推荐）。在群里添加机器人后复制 Webhook |
| `pushplus` | [PushPlus](https://www.pushplus.plus) 个人微信，需配置 `token` |

#### 企业微信 wework

```yaml
wechat:
  enabled: true
  type: wework
  webhook-key: 131d5793-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

- **只填 key**：程序会拼成 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`
- **也可粘贴完整 Webhook URL**，程序会自动识别

#### PushPlus

```yaml
wechat:
  enabled: true
  type: pushplus
  token: 你的PushPlus_token
```

### 5.3 分平台开关 platforms

仅控制**是否发微信**，不影响邮件。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `platforms.mercari` | `true` | 煤炉搜索上新/降价、关注卖家上新 |
| `platforms.yahoo` | `false` | 雅虎 |
| `platforms.rakuten` | `false` | 乐天 |

示例：只把煤炉通知推到微信：

```yaml
wechat:
  platforms:
    mercari: true
    yahoo: false
    rakuten: false
```

### 5.4 消息形式（实现说明）

- **企业微信**：先发 **news 图文**（商品首图 + 标题/价格），再发 **markdown**（原网站、顺通购买、关注 三个可点链接）。
- 首图使用 JPG 地址（`static.mercdn.net`，非 webp），以满足企业微信 picurl 要求。
- **PushPlus**：仅发送 markdown 文本。

调试：运行测试类 `WeChatNotifierTest`，推荐方法 `sendLikeProduction_newsAndMarkdown`。可用 `-Dwechat.test.itemId=真实商品ID` 指定煤炉商品。

## 6. 邮件通知 mail

### 6.1 发送开关与账号选择

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `mail.enabled` | `true` | 是否发送邮件；`false` 时只走微信（若已开）且通知仍视为成功以便入库 |
| `mail.from` | `qq` | 发信 SMTP 账号：`qq` 或 `netease`（163） |
| `mail.to` | `netease` | 收信地址：取对应账号的 `username` |

163 作发信时部分网络易被拒，注释中建议 `from: qq`。

### 6.2 邮箱账号 mail.qq / mail.netease

每个账号包含：

| 字段 | 说明 |
|------|------|
| `host` / `port` | SMTP 服务器，QQ 一般为 `smtp.qq.com:465` |
| `username` | 邮箱地址 |
| `password` | **授权码**（非 QQ/邮箱登录密码） |
| `imap-host` / `imap-port` | 清理发件箱用，QQ 为 `imap.qq.com:993` |
| `imap-password` | 可选；未填则复用 `password`。IMAP 与 SMTP 授权码不同时务必单独配置 |

QQ 邮箱需在设置中开启 POP3/SMTP/IMAP 并生成授权码。

### 6.3 发件箱自动清理 mail.cleanup

每天定时通过 IMAP 删除发件箱里**本程序发出的通知邮件**，避免 QQ 发件箱爆满。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `cleanup.enabled` | `true` | 是否启用定时清理 |
| `cleanup.cron` | `0 0 3 * * ?` | Cron 表达式，默认每天 **03:00**（`Asia/Shanghai`） |
| `cleanup.provider` | `qq` | 使用哪套邮箱做 IMAP：`qq` / `netease` |
| `cleanup.sent-folder` | `已发送` | IMAP 发件箱文件夹名；英文客户端可能是 `Sent Messages` |
| `cleanup.batch-size` | `200` | 每批最多删除封数 |
| `cleanup.max-batches` | `50` | 单次任务最多批次数 |

#### 如何识别「本程序发出的邮件」

1. **自定义头（新邮件）**  
   发送时自动加：`X-Bussiness-Notification: 1`

2. **主题关键词（历史邮件兜底）**  
   无上述头时，主题包含 `subject-keywords` 中任一词才删除：

| 默认关键词 | 对应场景 |
|------------|----------|
| `上新啦` | 煤炉/雅虎/乐天上新 |
| `的这些商品降价啦` | 降价通知 |
| `关注的用户上新` | 煤炉卖家关注 |
| `关注的用户降价啦` | 卖家降价 |

若只想按邮件头删除（更严格，不删主题相似的手动邮件）：

```yaml
mail:
  cleanup:
    match-subject-keywords: false
```

可自定义关键词列表：

```yaml
mail:
  cleanup:
    subject-keywords:
      - 上新啦
      - 降价
```

## 7. 配置示例

### 7.1 仅煤炉 + 企业微信 + QQ 发邮件（常见）

```yaml
mercari:
  enable: true
yahoo:
  enable: false
rakuten:
  enable: false

network:
  proxy:
    enabled: true
    host: 127.0.0.1
    port: 7897

notification:
  host: https://your-public-host:8111

wechat:
  enabled: true
  type: wework
  webhook-key: YOUR_WEBHOOK_KEY
  platforms:
    mercari: true
    yahoo: false
    rakuten: false

mail:
  enabled: true
  from: qq
  to: qq
  cleanup:
    enabled: true
  qq:
    username: your@qq.com
    password: SMTP授权码
    imap-password: IMAP授权码   # 与 SMTP 不同时填写
```

### 7.2 只收微信、不发邮件

```yaml
mail:
  enabled: false
wechat:
  enabled: true
  type: wework
  webhook-key: YOUR_KEY
```

### 7.3 三平台都抓，仅煤炉推微信

```yaml
mercari.enable: true
yahoo.enable: true
rakuten.enable: true

wechat.platforms.mercari: true
wechat.platforms.yahoo: false
wechat.platforms.rakuten: false
```

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| 微信收不到 | 检查 `enabled`、`webhook-key`；企业微信勿走代理；看日志 `微信通知` |
| 微信无首图 | 确认 `type: wework`；picurl 需 JPG；用 `WeChatNotifierTest` 验证 |
| 邮件 554 被拒 | 换 QQ 发信或检查授权码、发信频率 |
| 发件箱清理无效 | 确认 IMAP 已开启、`sent-folder` 名称、`imap-password` |
| 清理误删邮件 | 设 `match-subject-keywords: false`，仅依赖 `X-Bussiness-Notification` 头 |
| 关注链接打不开 | 修正 `notification.host` 与内网穿透 |

## 9. 修改配置后

修改 `application.yml` 后需**重启应用**生效。Cron 清理任务在应用运行期间按调度执行。

配置文件路径：`src/main/resources/application.yml`
